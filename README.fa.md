# Nova-Proxy — نسخهٔ شخصی و پاک‌سازی‌شده

این یک فورک خصوصی از پروژهٔ Nova-Proxy است که برای استفادهٔ شخصی بازبینی و
پاک‌سازی شده. تمام اتصالات به سازنده و اشخاص ثالث حذف شده‌اند.

> **می‌خواهید همین الان نصب کنید؟**
> برو سراغ **[`DEPLOY-NOW.fa.md`](DEPLOY-NOW.fa.md)** — راهنمای ۱۰ قدمی، فقط با
> داشبورد کلودفلر، بدون ترمینال، مخصوص کسی که دامنهٔ شخصی ندارد.
>
> این فایل که می‌خوانید مرجع فنی است: چه چیزی پیدا شد، چه چیزی حذف شد، و چرا.

## ۱. خلاصهٔ ماجرا

شما این پروژه را فورک کردید چون نسخهٔ عمومی‌اش مدام گزارش و بن می‌شد. هدف:
اجرای خصوصی روی حساب کلودفلر خودتان، فقط برای خودتان، بدون اینکه چیزی به
سازنده یا شخص ثالثی وصل باشد.

کل مخزن فایل‌به‌فایل بررسی شد. نتیجه در بخش ۴ آمده.

**وضعیت فعلی:** تمام اتصالات برگشتی به سازنده قطع شده‌اند. دیپلوی شما فقط با
شما و کلودفلر حرف می‌زند.

## ۲. مهم‌ترین نکته — چرا بن شدید

این را قبل از هر چیز بخوانید، چون از تمام تغییرات فنی مهم‌تر است:

> **بن‌شدن‌های قبلی از کد نبود. از این بود که سرویس را عمومی اجرا می‌کردید.**

خود کد سقف ۱۰ کاربر را هاردکد کرده و پیام خطایش صراحتاً می‌گوید دلیلش محدودیت
CPU کلودفلر است:

```js
let p = Number(e.NOVA_MAX_USERS) || 10;
if (u.length >= p) return ue({ success: !1,
  error: `User limit reached. This panel allows up to ${p} users to stay
          within Cloudflare's CPU limit. Set NOVA_MAX_USERS to raise it.` }, 400);
```

یعنی این ورکر **ذاتاً برای سرویس‌دهی عمومی طراحی نشده**. اگر دوباره عمومی‌اش
کنید، دوباره بن می‌شوید — هر چقدر هم کد تمیز باشد.

### چهار کاری که حتماً باید بکنید

۱. **مخزن را Private کنید** — تا کسی مسیرها و تنظیمات شما را نبیند.
۲. **لینک اشتراک را هیچ‌جا پخش نکنید** — نه کانال، نه گروه، نه دوستِ دوست.
۳. **`MAX_USERS` را کم بگذارید** (۱ تا ۵).
۴. **نام ورکر را بی‌ربط انتخاب کنید** — کلماتی مثل `vpn`، `proxy`، `nova`،
   `v2ray`، `tunnel` را در نام نگذارید.

## ۳. دو نسخه: Nova یا nova-mini؟

| | **Nova** (`worker.js`) | **nova-mini** (`examples/nova-mini/`) |
|---|---|---|
| حجم | ۱٫۳ مگابایت، مینیفای | ۵۳ کیلوبایت، خوانا |
| قابل بازرسی؟ | ❌ عملاً نه | ✅ در یک نشست می‌خوانیدش |
| پنل کاربران | ✅ | ✅ ساده |
| ربات تلگرام | ✅ | ❌ |
| WARP / تماس تصویری | ✅ | ❌ (UDP ندارد) |
| سهمیهٔ حجمی و انقضا | ✅ | ❌ |
| آی‌پی تمیز + تشخیص اپراتور | ✅ | ✅ |
| ساخت لیست اسکن | ❌ | ✅ |
| دیتابیس | KV + D1 | فقط KV |
| تست خودکار | ❌ | ✅ ۶۸ تست |

**توصیه:** اگر فقط برای خودتان می‌خواهید، **nova-mini** را انتخاب کنید. کل کدش
را می‌توانید بخوانید و مطمئن شوید چیزی پنهان نیست — که دقیقاً هدف اصلی شما بود.

`worker.js` امکانات بیشتری دارد ولی یک فایل مینیفای است و سورس اصلی‌اش هرگز
منتشر نشده. من همهٔ `fetch`های آن را بررسی کردم و اتصالات مشکوک را حذف کردم،
ولی صادقانه: **هیچ‌کس نمی‌تواند صددرصد تضمین کند در ۱٫۳ مگابایت کد فشرده چیزی
پنهان نمانده.**

## ۴. گزارش امنیتی — چه چیزی پیدا و حذف شد

### 🔴 بحرانی — ترافیک شما از سرور شخص ثالث رد می‌شد

رشته‌ای به‌صورت محاسباتی ساخته می‌شد تا در جست‌وجوی متنی ساده پیدا نشود:

```js
var et = [ (Proxy.name + "IP").toUpperCase(),                     // "PROXYIP"
           ("Cm" + URL.name[2] + "i" + URL.name[0]).toLowerCase(), // "cmliu"
           String(2407 * 300 - 10).split("").reverse().join("") ]; // "090227"
// نتیجه: PROXYIP.tp1.090227.xyz
```

وقتی `PROXYIP` تنظیم نشده بود، ترافیک کاربران به دامنهٔ متعلق به توسعه‌دهندهٔ
ثالث `cmliu` فرستاده می‌شد. آن دامنه می‌توانست مقصد و حجم ترافیک شما را ببیند.

**رفع:** حذف شد. حالا اگر `PROXYIP` ست نشده باشد، اول NAT64 امتحان می‌شود و در
غیر این صورت اتصال با خطای صریح رد می‌شود — به هیچ رلهٔ ناشناسی وصل نمی‌شود.

### 🔴 بحرانی — چهار پراکسی پیش‌فرض شخص ثالث (پنهان‌شده با base64)

```js
atob("cHJveHlpcC5meHhrLmRlZHluLmlv")      → proxyip.fxxk.dedyn.io
atob("d29ya2Vycy5jbG91ZGZsYXJlLmN5b3U=")  → workers.cloudflare.cyou
atob("cHJveHlpcC5qcC5meHhrLmRlZHluLmlv")  → proxyip.jp.fxxk.dedyn.io
atob("cHJveHlpcC5zZy5meHhrLmRlZHluLmlv")  → proxyip.sg.fxxk.dedyn.io
```

بر اساس دیتاسنتر کلودفلر یکی انتخاب و ترافیک از آن عبور می‌کرد.
**رفع:** حذف شد. فقط `PROXYIP` خودتان استفاده می‌شود.

### 🟠 تلمتری نصب به سرور سازنده

```js
await fetch("https://novaproxy.online/api/stats", {
  method: "POST",
  body: JSON.stringify({ type: "install", id: n })   // n = هش دامنهٔ شما
});
```

هنگام ست‌کردن رمز ادمین، هش SHA-256 دامنهٔ شما به سرور سازنده می‌رفت. اگرچه هش
بود، ولی چون دامنهٔ ورکر عمومی است، سازنده می‌توانست با هش‌کردن دامنه‌های
شناخته‌شده آن را معکوس کند. سوییچ خاموش‌کردن (`STATS_OPTOUT`) وجود داشت ولی
پیش‌فرض **روشن** بود.

**رفع:** کل تابع حذف شد؛ حتی رشتهٔ آدرس هم دیگر در فایل نیست.

### 🟠 ورک‌فلوی به‌روزرسانی خودکار از مخزن سازنده

`.github/workflows/nova-update-check.yml` هر روز ساعت ۴:۱۷ اجرا می‌شد،
`worker.js` را از `IRNova/Nova-Proxy` می‌گرفت و اگر `NOVA_UPDATE_MODE=automatic`
بود **مستقیم روی برنچ اصلی پوش می‌کرد** و Workers Builds دیپلویش می‌کرد.

یعنی سازنده می‌توانست هر کدی را روی ورکر شما اجرا کند — بدون تأیید شما.

**رفع:** فایل ورک‌فلو کاملاً حذف شد.

### 🟠 به‌روزرسانی از داخل پنل با توکن کلودفلر شما

مسیر `POST /admin/cloudflare-update` توکن API کلودفلر شما را می‌گرفت،
`worker.js` را از `raw.githubusercontent.com/IRNova/Nova-Proxy` دانلود می‌کرد و
با API کلودفلر روی حساب شما آپلود می‌کرد. چک SHA-256 داشت، ولی هش از همان
`version.json` مخزن سازنده می‌آمد — پس اگر سازنده هر دو را با هم عوض می‌کرد چک
بی‌فایده بود.

**رفع:** آدرس‌ها به مخزن خودتان تغییر کرد. **توصیه: این مسیر را اصلاً استفاده
نکنید** و به‌روزرسانی را دستی انجام دهید.

### 🟡 منابع راه دور تحت کنترل سازنده / اشخاص ثالث

| مورد | آدرس قبلی | وضعیت |
|---|---|---|
| اندپوینت‌های WARP | `IRNova/Tools/warp-endpoints.txt` | خاموش، مگر خودتان `WARP_ENDPOINTS_URL` را ست کنید |
| لیست IP تمیز | `IRNova/Tools/clean-ip` | خالی شد |
| لیست PROXYIP | `IRNova/Tools/all.json` | خالی شد |
| رنج‌های CF-CIDR | `cmliu/cmliu/CF-CIDR` | به `cloudflare.com/ips-v4` رسمی تغییر کرد |
| مبدل ساب | `SUBAPI.cmliussss.net` | خالی شد |
| قواعد Clash | `cmliu/ACL4SSR/...` | خالی شد |
| پسوند IATA | `<iata>.proxyip.cmliussss.net` | فقط با `PROXYIP_IATA_SUFFIX` |
| مخزن آینه | `IRNova/Nova-Proxy` | خالی شد |

### 🟡 تبلیغ اجباری داخل کانفیگ کاربران

هر لینک اشتراک یک نود تبلیغاتی داشت که کانال تلگرام سازنده را تزریق می‌کرد.
پنل خودش می‌گفت «این مورد در ورکر ثابت است، پس قابل خاموش‌کردن یا حذف توسط
فروشنده نیست.» → **حذف شد.**

### ⚪ بررسی شد و سالم بود

- `eval` یا `new Function` وجود ندارد — اجرای کد پویا نیست.
- UUID یا رمز هاردکدشده‌ای پیدا نشد (`00000000-...` فقط placeholder است).
- بک‌دور احراز هویت پیدا نشد؛ مقایسهٔ رمز constant-time است.
- `PANEL_RECOVERY=1` بک‌دور نیست؛ فقط استتار مسیر را خاموش می‌کند و نیاز به
  دسترسی به داشبورد کلودفلر خودتان دارد.
- وبهوک تلگرام با `secret_token` و بررسی `ChatID` محافظت می‌شود.
- API تلگرام فقط با توکن ربات **خودتان** صدا زده می‌شود.
- `CENTRAL_API` پیش‌فرض خالی است.

### فهرست نهایی دامنه‌هایی که ورکر می‌تواند به آن‌ها وصل شود

با بررسی همهٔ `fetch`های فایل، فقط این‌ها باقی مانده‌اند:

| دامنه | چرا |
|---|---|
| `api.cloudflare.com` | فقط با توکن و روی حساب خودتان |
| `api.cloudflareclient.com` | ثبت اکانت WARP (فقط اگر WARP را فعال کنید) |
| `api.telegram.org` | فقط با توکن ربات **خودتان** |
| `cloudflare-dns.com` | DoH برای resolve کردن مقصدها |
| `www.cloudflare.com/ips-v4` | لیست رسمی رنج‌های کلودفلر |
| `ipinfo.io` | 🟡 تنها شخص ثالث باقی‌مانده — فقط پرچم کشور |

**دربارهٔ `ipinfo.io`:** آدرس IP پراکسی شما را (نه ترافیک، نه IP کاربران) برای
گرفتن کد کشور می‌فرستد و فقط وقتی صدا زده می‌شود که در پنل صفحهٔ مربوطه را باز
کنید. خطرش ناچیز است. اگر بخواهید کاملاً صفر شود بگویید حذفش کنم (فقط پرچم
کشور را از دست می‌دهید).

## ۵. خطای ۱۱۰۱

### دو نوع کاملاً متفاوت وجود دارد

> این بخش مربوط به **Nova کامل** (`worker.js`) است. nova-mini مسیر `/healthz`
> ندارد و به‌خاطر سبکی‌اش معمولاً به ۱۱۰۱ نوع «ب» نمی‌خورد.

اول تشخیص دهید کدام را دارید:

```bash
curl -s https://<your-worker>/healthz
```

- **جواب JSON داد** (`{"ok":true,...}`) → ورکر سالم بالاست. مشکل از **مصرف CPU**
  است (نوع ب).
- **خودش هم ۱۱۰۱ داد** → ورکر اصلاً اجرا نمی‌شود (نوع الف).

این مسیر عمداً به دیتابیس و احراز هویت دست نمی‌زند، برای همین تشخیص قطعی است.

### نوع الف — ورکر بالا نمی‌آید

تقریباً همیشه یعنی **`nodejs_compat` فعال نیست**. در داشبورد برو
`Workers & Pages > ورکر > Settings > Runtime` و مطمئن شو فلگ `nodejs_compat`
هست و `compatibility_date` حداقل `2024-09-23` است.

### نوع ب — بالا می‌آید ولی بعد از مدتی می‌ترکد

مصرف CPU. این متغیرها مستقیماً روی آن اثر دارند:

| متغیر | پیش‌فرض کد | مقدار پیشنهادی | چه می‌کند |
|---|---|---|---|
| `NOVA_MAX_USERS` | ۱۰ | **۵** | سقف کاربر |
| `DIRECT_DIAL_CONCURRENCY` | ۲ | **۱** | اتصال موازی در هر دیال (۱ تا ۸) |
| `UPLOAD_QUEUE_MB` | ۱۶ | **۱۶** | سقف صف آپلود (۸ تا ۶۴) |
| `MONTHLY_CAP_GB` | ۰ (بی‌نهایت) | **۱۰۰** | بعد از عبور ۵۰۳ می‌دهد |
| `ENABLE_CRON` | خاموش | **۱** | نگهداری پس‌زمینه |

اگر باز هم گرفتید، سخت‌گیرانه‌ترش کنید: `NOVA_MAX_USERS=2`،
`DIRECT_DIAL_CONCURRENCY=1`، `UPLOAD_QUEUE_MB=8`.

### ارتباطش با بن‌شدن

در [ایشو ‎#145](https://github.com/IRNova/Nova-Proxy/issues/145) کاربری نوشته
«اخطار ابیوز اومد و پنل قطع شد». این و ۱۱۰۱ دو نشانه از **یک ریشه**‌اند:
مصرف بیش از حد منابع روی پلن رایگان.

- CPU زیاد → ۱۱۰۱
- درخواست/ترافیک زیاد → اخطار abuse و بن

سقف `MONTHLY_CAP_GB` دقیقاً برای همین است: قبل از اینکه کلودفلر شما را ببندد،
خودِ ورکر ۵۰۳ می‌دهد.

### رفع‌های CPU که از قبل داخل فایل هستند

هر کدام در باینری پیدا و تأیید شد که سالم‌اند (پچ‌های امنیتی ما به هیچ‌کدام دست
نزده‌اند):

| نسخه | رفع |
|---|---|
| 4.5.6 | ایندکس روی جدول اتصالات (`idx_active_connections_expiry`) |
| 4.6.0 | خطای رد‌نشدهٔ retry که سوکت را نشت می‌داد |
| 4.6.0 | لاگرِ throw کننده که اسلات را نشت می‌داد |
| 4.6.0 | تسک‌های پس‌زمینهٔ رد‌نشده |
| 4.6.1 | صفحهٔ طعمه (decoy) استاتیک — دیگر هر پروب یک fetch نیست |
| 4.6.2 | UDP غیر-DNS و هاست بلاک‌شده دیگر مسیر خطا نمی‌روند |
| 4.6.5 | مسیر `/healthz` بدون هیچ وابستگی |

## ۶. آی‌پی تمیز و تشخیص اپراتور

اگر دامنهٔ شخصی ندارید، این **حیاتی** است — `workers.dev` روی اکثر اپراتورهای
ایران فیلتر است.

### چرا کار می‌کند

به یک آی‌پی تمیز کلودفلر وصل می‌شوید ولی **SNI و Host را روی نام اصلی نگه
می‌دارید**. کلودفلر بر اساس SNI مسیریابی می‌کند، پس فیلترینگ دامنه دور می‌خورد:

```
vless://…@1.1.1.1:443?security=tls&sni=vpn.example.com&…&host=vpn.example.com#my-vpn
         ↑ آی‌پی تمیز              ↑ نام واقعی می‌ماند
```

### تشخیص خودکار اپراتور

ورکر از `request.cf` (که خود کلودفلر ست می‌کند و قابل جعل نیست) اپراتور را
تشخیص می‌دهد و لیست مناسب را می‌دهد:

| شرط | نتیجه |
|---|---|
| `country !== 'IR'` | `all` |
| ASN ‎44244 یا `irancell\|mtn` | `mtn` |
| ASN ‎197207 یا `mcci\|hamrah` | `mci` |
| ASN ‎57218 یا `rightel` | `rightel` |
| ASN ‎31549 یا `shatel` | `shatel` |
| بقیه | `ir` |

### ساخت لیست اسکن (فقط nova-mini)

پنل می‌تواند لیست کاندیدا برای اسکن بسازد:

- `GET /admin/api/scan-plan` → JSON
- `GET /admin/api/scan-plan.txt` → فایل `ip:port`، یکی در هر خط

هر دو نیاز به ورود دارند (وگرنه ۴۰۱). تعداد بین ۱۶ تا ۲۰۴۸ محدود می‌شود.
پورت‌های TLS: `443, 2053, 2083, 2087, 2096, 8443`.

فایل خروجی را در یک اسکنر آی‌پی (مثل NovaRadar روی دسکتاپ) بریزید و آی‌پی سالم
پیدا کنید. **خود ورکر نمی‌تواند اسکن کند** — کلودفلر اتصال TCP خام به آی‌پی
لخت را از داخل ورکر بلاک می‌کند.

> رنج‌های آی‌پی و پورت‌ها از پروژهٔ [NovaRadar](https://github.com/IRNova/NovaRadar)
> (لایسنس MIT) گرفته شده. هیچ‌کدام از منابع شخص ثالث یا SNI هاردکدشدهٔ آن
> پروژه استفاده نشد.

### فرمت لیست آی‌پی

اگر می‌خواهید از یک URL لیست بگیرید، پوشه‌ای بسازید شامل `mci.txt`، `mtn.txt`،
`rightel.txt`، `shatel.txt`، `ir.txt`، `all.txt` — هر کدام ساده و به شکل
`ip:port`. آدرس باید **https** باشد وگرنه ۴۰۰ می‌گیرید.

## ۷. متغیرهای محیطی

### nova-mini

| نام | نوع | لازم؟ | توضیح |
|---|---|---|---|
| `KV` | KV Binding | ✅ | نام باید **دقیقاً** `KV` باشد |
| `CLAIM_TOKEN` | **Secret** | ✅ | جلوی تصاحب پنل توسط غریبه را می‌گیرد |
| `MAX_USERS` | Text | ❌ | پیش‌فرض ۱۰ |
| `PROXYIP` | Secret | ❌ | نبودش = خطای صریح، نه رلهٔ پنهان |
| `UUID` | Secret | ❌ | |

### Nova کامل

علاوه بر بالا: دیتابیس D1 با نام بایندینگ **`DB`**، به‌علاوه متغیرهای مهار CPU
از بخش ۵.

### نام‌هایی که باید دقیقاً مطابق باشند

| چیز | مقدار |
|---|---|
| بایندینگ KV | `KV` |
| سکرت | `CLAIM_TOKEN` |
| فلگ سازگاری | `nodejs_compat` |
| تاریخ سازگاری | حداقل `2024-09-23` |
| بایندینگ D1 (فقط Nova) | `DB` |

### دربارهٔ `CLAIM_TOKEN`

بدون آن، **هر کسی** که آدرس `/admin/setup` را پیدا کند می‌تواند پنل شما را
تصاحب کند. رفتار تأییدشده:

| حالت | نتیجه |
|---|---|
| ست نشده | ✅ هر کسی پنل را می‌گیرد ⚠️ |
| ست شده + توکن غلط/نبود | ❌ ۴۰۳ `Add ?claim=<your CLAIM_TOKEN> to this URL.` |
| ست شده + درست + رمز <۱۰ حرف | ❌ ۴۰۰ `Use at least 10 characters.` |
| ست شده + درست + رمز خوب | ✅ ۳۰۳ → `/admin` |

ساخت توکن — در کنسول F12 مرورگر:

```js
crypto.randomUUID().replace(/-/g, '')
```

**`/admin/setup` یک‌بار مصرف است.** اگر توکن را گم کردید: `CLAIM_TOKEN` را در
داشبورد عوض کنید و Deploy بزنید. اگر رمز را گم کردید: کلید `admin.json` را از
KV پاک کنید و دوباره setup را اجرا کنید.

## ۸. تأیید و بازرسی کد

### تأیید فایلی که دیپلوی می‌کنید

```bash
sha256sum worker.js          # با SHA256SUMS مقایسه کنید
node scripts/verify-release.mjs
```

هش‌های کلیدی:

```
نسخهٔ اصلی سازنده (کامیت 2fd8c3c):
  036f2dc8af3170db9e5839e663cff4ffcee2d8255e9955f353798d054943c523

نسخهٔ پچ‌شدهٔ ما:
  4e294800f091689ef9d93a54c4a66f0e6d1893413c4196dd06d9da3f0ba441d4

بازیابی نسخهٔ دست‌نخورده:
  git show 2fd8c3c:worker.js > worker-original.js
```

`worker.js` فقط **۱٪** عوض شده (۱۰ خط از ۱۰۳۳) و **هیچ قابلیتی حذف نشده** —
پنل، کاربران، تلگرام، VLESS، WARP، DoH، استتار، سهمیه، آمار، D1، 2FA و healthz
همه با شمارش نشانه‌ها در برابر نسخهٔ اصلی تأیید شدند.

### خواندن `worker.js`

فایل مینیفای است ولی می‌شود خوانایش کرد:

```bash
npm install
npm run readable      # analysis/worker.readable.js می‌سازد
```

حدود ۱۰۰۰ خط فشرده به ~۱۶٬۰۰۰ خط قالب‌بندی‌شده تبدیل می‌شود. همین دستور بعدش
`scripts/verify-readable.mjs` را اجرا می‌کند که درخت نحوی هر دو فایل را مقایسه
می‌کند — قالب‌بندی فقط فاصله جابه‌جا می‌کند، پس درخت‌ها باید دقیقاً یکی باشند.

`analysis/` در `.gitignore` است و هرگز دیپلوی نمی‌شود.

> **این سورس اصلی را برنمی‌گرداند.** مینیفای‌شدن نام متغیرها، کامنت‌ها و ساختار
> فایل را دور می‌ریزد و هیچ‌کدام قابل بازسازی نیستند. قالب‌بندی کد را قابل
> بازرسی می‌کند، نه اصل.

### تست‌های nova-mini

```bash
cd examples/nova-mini
npm run check     # ۶۸ تست + بررسی تازگی باندل + dry-run
```

تست‌ها با mutation testing اعتبارسنجی شده‌اند — یعنی عمداً کد را خراب کردیم و
مطمئن شدیم تست‌ها می‌گیرند.

## ۹. نصب با ترمینال

> برای نصب بدون ترمینال → **[`DEPLOY-NOW.fa.md`](DEPLOY-NOW.fa.md)**

### nova-mini

```bash
cd examples/nova-mini
npm install
npm run setup                          # فضای KV می‌سازد و wrangler.jsonc را پر می‌کند
npx wrangler secret put CLAIM_TOKEN    # توکن را وارد کنید
npm run check                          # تست قبل از دیپلوی
npm run deploy
```

بعد برو به `https://<worker>.workers.dev/admin/setup?claim=<توکن>` و رمز ادمین
را بگذار.

### Nova کامل

```bash
npm install
npx wrangler login
npm run setup       # KV و D1 را می‌سازد
npx wrangler secret put CLAIM_TOKEN
npx wrangler deploy --dry-run    # تست
npx wrangler deploy
```

### تست محلی

```bash
cd examples/nova-mini
rm -rf .wrangler/state     # مهم: حالت قبلی را پاک کن
npx wrangler dev --local
```

اگر `.wrangler/state` پاک نشود، کلید `admin.json` قدیمی باعث می‌شود
`/admin/setup` صفحهٔ ورود نشان دهد و فکر کنید `CLAIM_TOKEN` خراب است.

### به‌روزرسانی

به‌روزرسانی را **دستی** انجام دهید. مسیر `cloudflare-update` داخل پنل را
استفاده نکنید. برای برگشت به نسخهٔ قبل، در داشبورد:
`Deployments > Rollback`.

## ۱۰. عیب‌یابی

| نشانه | علت | راه‌حل |
|---|---|---|
| `Not found` خالی در `/admin` | بایندینگ KV نیست یا نامش غلط است | نام را دقیقاً `KV` بگذارید |
| خطای ۱۱۰۱ | معمولاً `nodejs_compat` نیست | بخش ۵ |
| `No such module "node:async_hooks"` | همان بالا | فلگ را اضافه کنید |
| `Add ?claim=...` | توکن در URL نیست یا غلط است | `?claim=<توکن>` را اضافه کنید |
| به‌جای «Create password» صفحهٔ «Sign in» می‌بینم | setup قبلاً انجام شده | کلید `admin.json` را از KV پاک کنید |
| وصل می‌شوم ولی اینترنت ندارم | `PROXYIP` ست نشده | یک PROXYIP معتبر بگذارید |
| با آی‌پی تمیز هم کار نمی‌کند | آی‌پی سوخته | آی‌پی دیگری امتحان کنید (بخش ۶) |
| تماس واتساپ/فیس‌تایم کار نمی‌کند | UDP پشتیبانی نمی‌شود | nova-mini اصلاً UDP ندارد؛ در Nova از WARP استفاده کنید |
| رمز پنل را گم کردم | — | کلید `admin.json` را از KV پاک کنید |
| مسیر مخفی را گم کردم | — | `PANEL_RECOVERY=1` را موقتاً ست کنید |

دیدن لاگ زنده:

```bash
npx wrangler tail
```

دنبال `connection_slot_action_failed` یا `nova_relay_error` بگردید.
