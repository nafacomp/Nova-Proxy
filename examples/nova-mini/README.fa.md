# nova-mini

یک ورکر VLESS-over-WebSocket کمینه، خوانا و کاملاً متن‌باز.

**۲۰۷ خط کد واقعی. بدون مینیفای، بدون مرحلهٔ بیلد، بدون کد پنهان.**
هرچه اینجا می‌خوانید همان چیزی است که اجرا می‌شود.

این پروژه در پاسخ به این سؤال ساخته شد: «خودمان نمی‌توانیم یک ورکر با همان
کارکرد بسازیم؟» جواب: **هستهٔ تونل را بله، همین است. کل پنل را نه.**

---

## چرا این‌قدر کوچک‌تر است؟

| | Nova-Proxy | nova-mini |
|---|---|---|
| حجم آپلود | ۱٬۷۴۲ کیلوبایت | **۷.۲ کیلوبایت** |
| خطوط کد | ~۱۶٬۰۰۰ (بعد از خوانا‌سازی) | **۲۰۷** |
| مینیفای؟ | بله، سورس منتشر نشده | خیر |
| تست؟ | ندارد | ۹ تست |

اندازه‌گیری کردم که آن ۱.۳ مگابایت واقعاً چیست:

```
حجم کل worker.js            ۱٬۲۳۸٬۰۲۴ بایت
  آیکون‌های SVG درون‌خطی        ۲۵۷٬۳۳۴   ۲۰.۸٪
  دیتابیس فرودگاه/دیتاسنتر       ۴۶٬۴۷۷    ۳.۸٪
  تصاویر base64                 ۲۹٬۳۶۲    ۲.۴٪
```

یعنی **بیش از یک‌چهارم فایل فقط ظاهر پنل است** — نه منطق تونل. بقیه‌اش هم
عمدتاً پنل مدیریت، مدیریت کاربر، سهمیه، آمار مصرف، ربات تلگرام و تولید
لینک اشتراک است. خودِ تونل، همان چیزی که اینترنت شما را عبور می‌دهد،
همین ۲۰۷ خط است.

---

## چه چیزی دارد

- پروتکل VLESS روی WebSocket (دستور TCP)
- آدرس IPv4، IPv6 و دامنه
- پشتیبانی از early-data (بایت‌های اول در هدر handshake، برای کاهش تأخیر)
- fallback به `PROXYIP` **فقط اگر خودتان تنظیم کنید**
- هر مسیری غیر از WebSocket یک ۴۰۴ سادهٔ بی‌نشان می‌گیرد

## چه چیزی ندارد (صادقانه)

اینها را عمداً ننوشتم، چون هرکدام روزها کار و تست می‌خواهد:

- پنل مدیریت وب
- چند کاربر، سهمیه، انقضا، محدودیت سرعت
- آمار مصرف و لاگ
- تولید خودکار لینک اشتراک (Clash / sing-box / v2rayN)
- ربات تلگرام
- UDP و در نتیجه تماس تصویری/صوتی (این محدودیت خود Cloudflare Workers است)
- استخر IP تمیز، WARP، زنجیرهٔ پراکسی، DoH، مسیریابی بر اساس کشور

اگر این‌ها را می‌خواهید، نسخهٔ پچ‌شدهٔ Nova-Proxy در همان مخزن گزینهٔ عملی‌تری است.

## راه‌اندازی

```bash
npm install
npx wrangler login

# UUID خودتان را بسازید و به‌صورت رمزنگاری‌شده ست کنید
npx wrangler secret put UUID          # مثلاً با: uuidgen

# اختیاری، فقط اگر اتصال مستقیم کار نکرد
npx wrangler secret put PROXYIP       # مثلاً: 1.2.3.4  یا  1.2.3.4:443

npm run check      # syntax + ۹ تست + dry-run
npm run deploy
```

`UUID` را داخل `wrangler.jsonc` ننویسید — آنجا رمزنگاری نمی‌شود و در گیت لو می‌رود.

### تنظیم کلاینت

| فیلد | مقدار |
|---|---|
| Protocol | VLESS |
| Address | `<worker>.<subdomain>.workers.dev` |
| Port | ۴۴۳ |
| UUID | همان که ست کردید |
| Network | ws |
| Path | `/` |
| TLS | فعال |
| SNI | همان دامنه |

## چرا این امن‌تر است

سه موردی که در ممیزی Nova-Proxy پیدا شد و **اینجا اصلاً وجود ندارند**:

1. **رلهٔ مخفی شخص ثالث.** آنجا وقتی PROXYIP خالی بود ترافیک به دامنه‌ای
   می‌رفت که اسمش در زمان اجرا از عبارات محاسباتی ساخته می‌شد تا در
   جست‌وجوی متنی پیدا نشود. اینجا اگر PROXYIP نباشد، اتصال با خطای صریح
   رد می‌شود — به هیچ‌جای ناشناسی وصل نمی‌شود.
2. **تلمتری نصب.** آنجا هش دامنهٔ شما به سرور سازنده می‌رفت. اینجا هیچ
   درخواست خروجی‌ای به‌جز خودِ مقصد کاربر وجود ندارد.
3. **به‌روزرسانی خودکار از مخزن سازنده.** اینجا کد فقط وقتی عوض می‌شود که
   خودتان `npm run deploy` بزنید.

می‌توانید خودتان تأیید کنید — کل فایل ۲۸۷ خط است و در یک نشست خوانده می‌شود.

## دربارهٔ خطای 1101

یکی از ریشه‌های 1101 در نسخهٔ اصلی، promise های رد‌شدهٔ مدیریت‌نشده بود که
ورکر را گیر می‌انداختند. اینجا هر مسیر خطا صریحاً گرفته می‌شود و
`ctx.waitUntil` هیچ‌وقت یک rejection را بیرون نمی‌دهد (به کامنت داخل `pump` نگاه کنید).

ضمناً همان قانون همیشگی: `compatibility_flags: ["nodejs_compat"]` را نگه دارید.

## محدودیت‌هایی که باید بدانید

- **زیر بار واقعی تست نشده.** ۹ تست پارسر هدر را پوشش می‌دهند (شامل تکه‌تکه
  رسیدن بایت‌ها، UUID اشتباه، و IPv6). ولی من نتوانستم یک کلاینت واقعی به
  یک ورکر واقعی وصل کنم و ترافیک عبور دهم. قبل از تکیه‌کردن، خودتان با
  v2rayN یا Hiddify تستش کنید.
- **UDP ندارد**، پس تماس تصویری کار نمی‌کند. این محدودیت پلتفرم است نه کد.
- **بدون مبهم‌سازی.** اگر شبکه‌ای الگوی VLESS-over-WS را فینگرپرینت کند،
  این هم مثل بقیه شناسایی می‌شود. دامنهٔ شخصی و CDN کمک می‌کند.
